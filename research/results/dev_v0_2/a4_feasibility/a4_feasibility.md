## กฎของ A4
A4 ใช้คำตอบของ A2 เป็นค่าเริ่มต้น และให้ A3v2_2e เป็นผู้เสนอเปลี่ยนคำตอบ ข้อเสนอจะได้รับการยอมรับเฉพาะเมื่อผ่าน gate ตามหลักการ 3 ข้อของผู้วิจัย

| Gate | เงื่อนไข |
|---|---|
| **P3 numeric lock** | A2 ตรวจตัวเลขครบทุกด้าน (สถานะ TRUE/FALSE, ไม่มี issue, มีหน่วย, งวดตรงกับที่ claim ระบุ, ไม่มีตัวเลขหลายเวอร์ชัน) และ A3 ไม่พบ validity flag → คงคำตอบ A2 |
| **P3 numeric re-check** | ถ้า A3 พบ SCOPE_MISMATCH, PERIOD_MISMATCH หรือ FUTURE_PERIOD หรือ A2 ตรวจตัวเลขไม่ครบ → ยอมรับผลตรวจ deterministic ของ A3 (N1/N2) |
| **P1 เปลี่ยนเป็น INSUFFICIENT** | สัญญาณ D-sup หรือ E1 อย่างเดียวไม่พอ ต้องผ่านทุกข้อต่อไปนี้: ไม่ติด numeric lock; A3 ไม่ได้ยืนยันหลักฐานที่รองรับคำตอบของ A2; ถ้ามาจาก D-sup ต้องมีคำประเมินที่ไม่มีเกณฑ์จริง; ถ้ามาจาก E1 ต้องไม่ใช่กรณีที่ R ตอบซ้ำกับ A2 |
| **P2 เปลี่ยนเป็น SUPPORTED/CONTRADICTED** | ไม่นับแค่การเห็นตรงกัน ต้องผ่าน 3 ข้อ: (1) **evidence scope:** finding เป็น VALID, quote VERIFIED, งวดเป็น EXACT_MATCH หรือ COMPATIBLE_AFTER_VERIFIED_DERIVATION, ไม่มี definition mismatch และไม่ใช่ข้อความคาดการณ์หรือเจตนา (2) claim ต้อง DECIDABLE และไม่มีคำประเมินที่ไม่มีเกณฑ์ (3) **assertion coverage:** SUPPORTED ต้องรองรับครบทุก assertion; CONTRADICTED ต้องมี assertion ที่ถูกแย้งโดยไม่มีหลักฐานรองรับ; claim เชิงสาเหตุต้องมี finding ที่ตอบเรื่องสาเหตุ (CAUSE) |

## ข้อสรุป: A4 คุ้มที่จะพัฒนาต่อหรือไม่
**คุ้มที่จะพัฒนาต่อในระดับ "มีแนวโน้ม" แต่ dev ชุดนี้ยืนยันไม่ได้ว่า A4 จะชนะบน gold**

**สัญญาณที่ดี**
- A4 เปลี่ยนคำตอบน้อยลง (12 ข้อ จาก 2e 17 ข้อ) แต่แม่นขึ้น: precision 92% เทียบกับ 82%
- regression ลดจาก 3 เหลือ 1 และยังเก็บการแก้ที่ถูกไว้ได้ 11/14
- 3 ใน 11 การแก้มาจาก numeric re-check แบบ deterministic ซึ่งเป็นส่วนที่น่าเชื่อถือที่สุด

**ข้อจำกัดสำคัญ**
1. **A4 ยังไม่ชนะ 2e บน dev** (63 กับ 64) ประโยชน์ของ A4 คือลดความเสี่ยง ไม่ได้เพิ่มคะแนน
2. **dev ชุดนี้เป็นข้อมูลที่ 2e ถูกพัฒนาบนมัน** บน dev 2e ทำพังแค่ 3 ข้อ แต่บน gold ทำพัง 15 ข้อ dev จึงวัดความสามารถในการกัน regression ซึ่งเป็นจุดประสงค์หลักของ A4 ได้น้อยมาก
3. **safeguard 2 ตัวไม่เคยทำงานบน dev:** numeric lock กับ evidence scope/coverage ยังไม่รู้ว่าช่วยได้จริงหรือไม่
4. **ข้อที่ทำพังรูปแบบ PG-05 ผ่านทุก gate:** claim เชิงสาเหตุที่ A3 มีหลักฐานจริงและผ่านการตรวจ แต่ตีความเกินหลักฐาน ซึ่งตรงกับความล้มเหลวหลักของ A3 v1 ในหมวดตีความ ไม่มี gate ใดที่ใช้สัญญาณใน trace แล้วกันได้
5. abstention guard ยังปรับสมดุลไม่ได้: ปิดการแก้ที่ถูก 2 ข้อ เพื่อกันการทำพังได้ 1 ข้อ
6. n = 12 การเปลี่ยน ทำให้ CI ของ precision กว้าง (65–99%)

**ขั้นต่อไปที่แนะนำ** (ยังไม่ได้ทำ)
- ล็อกกฎของ A4 ตามที่เป็นอยู่ ห้ามปรับเพิ่มบน dev-v0.2 เพราะจะยิ่ง overfit
- ทดสอบบนชุด claim ใหม่ที่ทั้ง 2e และ A4 ยังไม่เคยเห็น เพื่อดูว่า gate กัน regression ได้จริงหรือไม่
- ถ้าจะแก้ปัญหาแบบ PG-05 ต้องเพิ่มการตรวจ "หลักฐานรองรับคำว่าเป็นสาเหตุหลักหรือไม่" ซึ่งต้องเรียก LLM เพิ่ม และอยู่นอกขอบเขตของ offline study นี้
