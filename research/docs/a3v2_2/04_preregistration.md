# Preregistered evaluation plan: A3 v2.2 บน heldout-v1

> **สถานะ: ร่าง ยังไม่ได้ลงทะเบียน**
>
> - แผนนี้จะมีผลเมื่อผู้วิจัยลงชื่อ ลงวันที่ และ freeze ไฟล์ (hash) **ก่อน**ติด label ชุด heldout-v1
> - หลัง freeze ห้ามแก้ ถ้าจำเป็นต้องแก้ ให้ทำ amendment ที่ระบุเหตุผลและวันที่

## 1. Arm (กำหนดล่วงหน้า)

| Arm | รายละเอียด | ประเภท |
|---|---|---|
| A2 | baseline เดิม | รันจริง |
| RG-0.1 | A3 v2.1.1 ตามที่เป็นอยู่ | replay ของ R |
| RG-0.2 | + G3 + G6 | replay |
| RG-0.2b | + G3b (หลักฐานที่อ้างต้องถูกอ้างในผลสุดท้ายและผ่านการตรวจ) + G6 | replay |
| RG+C | RG-0.1 + C-system | replay (post-hoc บน trace) |
| RG+A | RG-0.1 + decidability gate (G1 + G4) | ต้องเรียก LLM เพิ่มขั้น decidability |
| **RG+A+G3+G6 (หลัก)** | RG-0.2 + decidability gate (G1 + G4) | เรียก LLM เหมือน RG+A |
| (ระยะ 2, ถ้าได้อนุมัติ) RG+A2-full | + G2 / G5 จากฟิลด์ใหม่ของ reviewer | รัน R ใหม่ทั้งหมด |

- **ทุก arm ใช้ชุด claim เดียวกัน, temperature 0, model เดียวกับ v2.1.1 และ seed ของ bootstrap คงที่ (20261118)**
- **C-category ไม่ใช่ arm** เพราะใช้ข้อมูลที่ระบบไม่รู้ตอนรัน

## 2. Endpoint และสถิติ

### Primary

- **Accuracy ของ RG+A+G3+G6 เทียบ A2** ทดสอบด้วย McNemar exact แบบจับคู่ และ paired bootstrap 95% CI ของผลต่าง (10,000 resamples)

### Secondary (ทดสอบตามลำดับ)

1. RG+A+G3+G6 เทียบ RG-0.1
2. RG+A+G3+G6 เทียบ RG+C

**การแก้ปัญหาทดสอบหลายครั้ง:** ใช้ Holm กับสามการเปรียบเทียบข้างบน (α = 0.05)

### Descriptive (ไม่ทดสอบ)

- macro-F1
- recall ของ INSUFFICIENT
- ความแม่นของการยอมรับการเปลี่ยนเป็นคำตอบเด็ดขาด (Wilson CI)
- correction / regression เทียบ A2 (Wilson CI)
- **RG − R และ RG − A2 แยกกัน** (report 1.1)
- ผลแยกตามประเภท claim
- สัดส่วน decidability ที่เป็น UNKNOWN
- จำนวนครั้งที่แต่ละกฎ (G1–G6) ทำงาน และผลของแต่ละครั้งเทียบ gold

## 3. Acceptance criteria ของ v2.2 (ต้องผ่านทุกข้อ)

| # | เกณฑ์ | ค่าของ v2.1.1 บน dev (อ้างอิงเท่านั้น) |
|---|---|---|
| AC1 | Accuracy ≥ A2 (point estimate) และขอบล่างของ 95% CI ของ (v2.2 − A2) > −8 pp | −2.8 pp |
| AC2 | Accuracy > RG-0.1 (point estimate) | — |
| AC3 | ความแม่นของการยอมรับการเปลี่ยนเป็นคำตอบเด็ดขาด ≥ 70% | 36% |
| AC4 | Regression rate เทียบ A2 ≤ 7% | 13.5% |
| AC5 | Recall ของ INSUFFICIENT ≥ recall ของ A2 − 5 pp | A2 68% / RG 46% |
| AC6 | Accuracy ของ numerical ≥ RG-0.1 − 1 ข้อ | 90% |
| AC7 | ไม่มี prediction ที่เป็น ERROR และต้นทุนอยู่ในงบที่อนุมัติ | 0 error |

### Power (ต้องรายงานในเล่ม)

- **n = 120 ตรวจจับได้ราว 10 pp:** ถ้าข้อที่ตอบต่างกันมีประมาณ 15% ของทั้งหมด ผลต่างที่ McNemar ตรวจได้ที่ power 80% (α 0.05) คือราว 10 pp
- **ถ้าต้องการตรวจได้ 5 pp:** ต้องใช้ราว 470 ข้อ
- **ผลต่างเล็กกว่านี้จึงจะ "ไม่มีนัยสำคัญ" แม้ว่าจะมีอยู่จริง** เพราะเหตุนี้ AC1 จึงใช้ทั้ง point estimate และขอบล่างของ CI แทนการทดสอบ superiority

## 4. การตีความ (กำหนดล่วงหน้า)

- **ผ่านทุก AC:** v2.2 "ดีกว่าหรือไม่ด้อยกว่า A2" บนชุดนี้
- **ผ่าน AC3–AC5 แต่ไม่ผ่าน AC1:** ระบบระมัดระวังขึ้นแต่ยังไม่ชนะ A2 ให้รายงานตามตรง
- **RG+C ≥ RG+A+G3+G6:** รายงานว่าการไม่เปลี่ยนคำตอบสำหรับ claim ที่ไม่ใช่ตัวเลข ให้ผลไม่แย่กว่า agentic review แบบมี decidability
- **ผล dev-v0.2 ทั้งหมด** (รวม offline ablation) อยู่ในบท "development" เท่านั้น ห้ามนำมารวมกับผลของ held-out

## 5. สิ่งที่ห้ามทำหลังเห็นผล

- ห้ามปรับกฎหรือ prompt แล้วรันซ้ำบน heldout-v1
- ห้ามตัด claim ออกหลังเห็นผล ยกเว้นข้อที่ตรวจพบภายหลังว่าผิดกติกาก่อนรัน เช่น วันตัดหลักฐานผิด ต้องบันทึกเหตุผลและรายงานผลทั้งก่อนและหลังตัด
- ห้ามเปลี่ยน primary endpoint
