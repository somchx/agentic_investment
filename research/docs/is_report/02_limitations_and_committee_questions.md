ใช้ประกอบบทที่ 5 และเตรียมสอบ IS ตัวเลขทุกตัวมาจากผลที่ freeze แล้ว (`results/is_report/tables/`, `evaluation.json`) หรือเอกสารที่อ้างไว้

## A. ข้อจำกัดของงานวิจัย

### A1. เฉลย (Gold)
1. **เฉลยไม่ได้มาจากผู้เชี่ยวชาญที่เป็นคนโดยตรง:** มาจาก LLM 3 ตัว → AI-assisted adjudication → ผู้วิจัยทบทวน (`llm_annotated_ai_adjudicated_researcher_reviewed`)
2. **ความเห็นตรงกันต่ำในหมวดตีความ/กำกวม:** α = 0.436 / 0.377 (numerical 0.862)
3. **A2 ถูก 84/100 ในข้อที่ annotator เห็นตรงกัน แต่ถูก 19/50 ในข้อที่เห็นไม่ตรงกัน** ส่วนหนึ่งของ "ความผิด" จึงสะท้อนความกำกวมของ task มากกว่าความผิดของระบบ
4. ไม่มีเกณฑ์ร่วมที่นิยามไว้ก่อนสำหรับคำอย่าง "primarily", "material", "strong"
5. การ audit Gold 25 ข้อในเอกสาร 13 ทำโดย AI คนเดียว ไม่ใช่ adjudication อิสระ

### A2. ชุดข้อมูล
6. claim ร่างโดย Claude Opus 5.5 โดยไม่ได้อ่านรายงานก่อน และไม่ได้แก้โดยคน ถ้อยคำอาจคล้ายรายงานทำให้ค้นง่ายขึ้น
7. โมเดลตระกูลเดียวกัน: ผู้ร่าง claim และ annotator 1 ตัวเป็น Claude ส่วนโมเดลที่ทดสอบเป็น Claude Sonnet 4.5
8. 10 บริษัทขนาดใหญ่ของสหรัฐฯ เท่านั้น
9. dev-v0.2 มีเพียง 72 ข้อ และ 3 บริษัทซ้ำกับ Gold

### A3. การออกแบบและสถิติ
10. **Power จำกัด:** n = 150 ตรวจผลต่างได้ราว 9 pp (prereg) ผลต่างที่เล็กกว่าอาจมีจริงแต่ไม่มีนัยสำคัญ
11. รันครั้งเดียว โมเดลเดียว temperature 0 ไม่ได้วัดความแปรปรวนระหว่างการรัน
12. ผลแยกหมวด (n = 50) และแยกกลไกเป็นเชิงพรรณนา ไม่ใช่การทดสอบ
13. **Gold exposure:** A3 v2 ออกแบบจาก error analysis ของ v1 บน Gold 23 ข้อ (เปิดเผยใน prereg §2) และ Gold ถูกเปิดดูรายข้อแล้วใน post-hoc analysis จึงใช้เป็น blind test ซ้ำไม่ได้
14. **Adaptive overfitting บน dev:** dev +11 → Gold −5

### A4. ระบบ
15. Retrieval BM25 ค่าเดียว ไม่มี embedding และไม่ได้ปรับค่า
16. ตารางใน HTML ถูกแบนเป็นข้อความ, period ของหลักฐานอิงระดับเอกสาร, inline XBRL ระดับ segment ไม่ได้ใช้
17. numeric engine รองรับ 11 metric และ 2 measure (level, yoy) ระดับบริษัทรวม
18. guard ตรวจรูปแบบของหลักฐาน ไม่ตรวจความหมาย

### A5. การวัดผล
19. strict label match ไม่ได้วัดคุณภาพของหลักฐาน: คำตอบถูกบางข้อมาจากเหตุผลผิด (4/10 correction ของ A3v2_2e ตามเอกสาร 13)
20. ไม่ได้วัด evidence precision / recall เพราะหลักฐานในเฉลย 71/150 ข้อเป็นตัวเลขจากตาราง ไม่ใช่ข้อความคำต่อคำ
21. ต้นทุนเป็น list price; latency วัดจากการรันแบบเรียงทีละข้อครั้งเดียว

### A6. กระบวนการ
22. Gold run รอบแรกหยุดเพราะ worktree ถูกลบ (เสีย ≈ $22.5) แก้ด้วย amendment ที่ไม่เปลี่ยนโค้ด / prompt / เกณฑ์ และไม่ได้เทียบผลรอบนั้นกับเฉลย
23. เอกสาร SEC ดาวน์โหลดใหม่หลังเหตุขัดข้อง raw hash ไม่ตรง manifest (EDGAR แทรก `<script>`) ยืนยันเนื้อหาด้วย content hash + cache replay
24. A4 และแผน SAV เป็น post-hoc / future work ไม่มีผลยืนยัน

## B. คำถามที่กรรมการอาจถาม และแนวคำตอบ

### B1. ผลหลักและการตีความ
**Q1. ระบบที่เสนอ (A3) แพ้ A2 แล้วงานวิจัยนี้มีคุณค่าอะไร**
- คำถามวิจัยคือ "contradiction-aware ช่วยหรือไม่" คำตอบที่ได้ตาม preregistration คือ "ไม่ช่วยในเงื่อนไขนี้" ซึ่งเป็นข้อค้นพบ
- ได้ข้อค้นพบเชิงบวกด้วย: การตรวจตัวเลขแบบ deterministic เพิ่ม +6 pp (p = 0.012) ที่ต้นทุนเท่าเดิม
- error analysis อธิบายกลไกที่ทำให้แพ้ได้ (guard ตรวจความหมายไม่ได้, over-abstention, ชั้นตรวจหลักฐานตัดหลักฐานจริง)

**Q2. −3.3 pp ไม่มีนัยสำคัญ แปลว่า A3 เท่ากับ A2 หรือเปล่า**
- ไม่ได้แปลว่าเท่ากัน แปลว่าไม่มีหลักฐานพอว่าต่างกัน CI [−10.0, +3.3] ครอบคลุมทั้งแย่ลงมากและดีขึ้นเล็กน้อย
- แต่ A3 ไม่ผ่านเกณฑ์ที่ตั้งไว้ก่อนทุกข้อหลัก (AC1–AC4) และแพงกว่า ≈ 7 เท่า จึงไม่มีเหตุผลเลือกใช้

**Q3. ทำไมไม่ปรับ A3 แล้วรันใหม่จนชนะ**
- เพราะจะเป็นการปรับระบบให้เข้ากับข้อสอบ ผลจะไม่ใช่หลักฐานที่เชื่อถือได้ ตัวอย่างที่เห็นแล้วคือ dev: +11 แต่ Gold −5
- preregistration กำหนดให้ประเมินครั้งเดียว

**Q4. SR ได้ 68% ใกล้ A2 แล้วทำไม A3 ที่ซับซ้อนกว่าได้น้อยกว่า**
- SR ไม่ยึดคำตอบเดิมแบบเดียวกับ reviewer ของ A3 และถอยไปเป็น INSUFFICIENT ได้ถูกจังหวะในหมวดตีความ (recall 9/16)
- A3 มี gate ความระมัดระวังที่ลดคำตอบโดยไม่ขึ้นกับความไม่แน่นอน (D-sup, E1)

### B2. เฉลยและข้อมูล
**Q5. เฉลยมาจาก LLM จะเชื่อได้อย่างไร**
- มีผู้วิจัยทบทวนและ Approved ครบ 150 ข้อ, มี vote pattern, rationale, evidence และ sha256
- รายงาน α ตามจริงและยอมรับเป็นข้อจำกัด; หมวดตัวเลขเชื่อถือได้สูง (α 0.862)
- audit 25 ข้อพบว่าความกำกวมกระจายเท่ากันทั้งฝั่ง correction และ regression จึงไม่พบหลักฐานว่าเฉลยลำเอียงต่อ A3

**Q6. ใช้ Claude ร่าง claim / annotate แล้วทดสอบด้วย Claude มี bias ไหม**
- เป็นข้อจำกัดที่ยอมรับ (A2.7) annotator มีสามตระกูล และเฉลยผ่านการทบทวนโดยผู้วิจัย
- ถ้ามี bias จะเอื้อทุก arm เท่ากัน เพราะทุก arm ใช้โมเดลเดียวกัน

**Q7. 150 ข้อน้อยไปหรือไม่**
- ตรวจผลต่างได้ราว 9 pp; ผลต่างที่สังเกตได้ (−3.3) เล็กกว่านั้นมาก ข้อสรุปจึงระวังว่า "ไม่พบหลักฐานว่าดีกว่า"
- งานต่อไปเสนอ blind test ≈ 400 ข้อ

### B3. ความถูกต้องของกระบวนการ
**Q8. Gold ถูกใช้ออกแบบระบบหรือไม่ (leakage)**
- เปิดเผยใน prereg §2: A3 v2 รุ่นแรกได้แนวคิดจาก error analysis ของ v1 บน Gold 23 ข้อ และ INSUFFICIENT adjudication 44 รายการ
- การเปิดเผยนี้ทำให้ผลเอียงเข้าข้าง A3 ถ้ามี; แม้อย่างนั้น A3 ก็ยังไม่ชนะ

**Q9. รอบแรกที่หายไปเลือกทิ้งเพราะผลไม่ดีหรือเปล่า**
- ไม่ใช่: รอบแรกหยุดที่ A3v2_2e 43/150 เพราะ worktree ถูกลบ ไม่เคยเทียบกับเฉลย (`11_…`) เขียน amendment ก่อนรันใหม่ และใช้โค้ด / prompt / config เดิมทุก byte (hash ตรง)

**Q10. ทำซ้ำได้อย่างไร**
- ทุก LLM response อยู่ใน cache ที่ key ด้วย hash ของ request; รันซ้ำแบบ offline ได้คำตอบเดิมโดยไม่เสียเงิน
- SHA256SUMS ของ run, code bundle hash, prereg hash, corpus pin; `scripts/is_report_assets.py` สร้างตารางและภาพจากไฟล์ freeze

**Q11. temperature 0 ยัง non-deterministic ได้ จัดการอย่างไร**
- รันจริงครั้งเดียวแล้วใช้ cache เป็นผลทางการ; ความแปรปรวนระหว่างการรันไม่ได้วัด (ข้อจำกัด A3.11)

### B4. เทคนิค
**Q12. ทำไมใช้ BM25 ไม่ใช้ embedding**
- ตั้งค่าไว้ล่วงหน้าค่าเดียวเพื่อควบคุมตัวแปร; error analysis พบว่า retrieval ไม่ใช่สาเหตุหลักของ regression
- เป็นข้อจำกัด (A4.15)

**Q13. guard ทำงานอย่างไร และทำไมไม่ช่วย**
- ตรวจว่าหลักฐานที่ใช้เปลี่ยนคำตอบมีจริง quote ตรง งวดถูก บริษัทถูก
- ข้อเสนอเสีย 5 ข้อผ่านทุก check รูปแบบแต่ผิดที่ความหมาย (scope, ศัพท์, เหตุผลเชิงสาเหตุ) guard จึงรับข้อเสนอเสียในสัดส่วนที่ไม่ต่างจากข้อเสนอดี

**Q14. Over-abstention คืออะไร เกิดขึ้นได้อย่างไร**
- A3v2_2e ทำนาย INSUFFICIENT 52 ครั้ง (เฉลยมี 44) ถูก 26 (50%) regression 11/15 เป็นการถอยจากคำตอบที่ถูกไปเป็น INSUFFICIENT
- มาจาก gate ที่ออกแบบบน dev ซึ่งมีสัดส่วน INSUFFICIENT สูงกว่า

**Q15. ต้นทุน 7 เท่าคิดอย่างไร**
- median list price ต่อ claim: A3v2_2e $0.141 vs A2 $0.0195 (ตาราง 4.5); ค่าที่จ่ายจริงของ run ทางการ $23.24

### B5. ภาพรวมและอนาคต
**Q16. ถ้าทำต่อ จะทำอะไร**
- ตัวแทนหลักฐานแบบมีโครงสร้าง (ตาราง / inline XBRL / period ระดับประโยค), ตรวจระดับ assertion, เกณฑ์ร่วมสำหรับคำประเมิน, selective verification (A4) และ blind test ชุดใหม่ที่มนุษย์ annotate (เอกสาร 14)

**Q17. A4 ที่ทำได้ 63/72 บน dev ทำไมไม่รายงานเป็นผล**
- เป็น post-hoc exploratory: กฎเลือกหลังเห็น dev trace และได้แรงบันดาลใจจากผล Gold; dev ไม่ใช่ข้อมูลใหม่ จึงเป็นเพียงข้อเสนอสำหรับอนาคต

**Q18. งานนี้บอกอะไรต่อผู้ใช้ AI ในการเงิน**
- ให้ใช้การคำนวณที่ตรวจสอบได้สำหรับข้อตัวเลข และระวังการตีความเชิงสาเหตุของ LLM; การเพิ่มขั้น agentic ไม่ได้ทำให้แม่นขึ้นเสมอ และเพิ่มต้นทุนชัดเจน
