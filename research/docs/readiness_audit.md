# Repository readiness audit — ReasonCheck research pipeline

Audit date: 2026-11-10. Scope: `research/` and the parts of `backend/app/core/` it reuses.
Method: read every engine / experiment / script module, ran the offline test suite (87 passed),
and probed the gold dataset, the corpus and the XBRL extractor directly. Findings below are
observed, not assumed; anything not verified says so.

## 0. Summary

The repository already contains a working, offline-testable experiment engine for all four
approaches (A1 conventional RAG, A2 RAG + deterministic verification, A3 contradiction-aware,
SR self-reflection), with point-in-time retrieval, deterministic numeric verification, citation
validation, a paid-call approval gate, a response cache, immutable run directories, metrics and
paired statistics. It is **not** built on LangGraph: the approaches are plain Python functions
(`research/experiments/*.py`).

Blocking issues found before any official run:

| # | Issue | Effect | Status after this work |
|---|---|---|---|
| B1 | Final gold labels exist only in `datasets/workbooks/Final_Gold_v1.xlsx`; nothing in the engine reads them | No metric can be computed on the gold split | Fixed: evaluation-only reference loader |
| B2 | `eligible_filings` counts `10-K/A` as the `10-K` slot. TSLA's 10-K/A (2026-04-30, Part III only, 145k chars) hides the real FY2025 10-K for 8 gold claims (TSLA-02, 03, 05, 07, 10, 11, 13, 15) | Those claims cannot see Tesla's annual financial statements | Fixed: an amendment never displaces the original |
| B3 | No LangGraph implementation | The required framework is missing | Implemented (`research/graphs/`) |
| B4 | Experiment model is `claude-sonnet-4-5-20250929` (app default); one gold annotator was Claude Opus 5.5 | Same-vendor model family on both sides of the evaluation | Not fixable in code; reported as a validity risk (§5) |

## 2. Missing research components

1. LangGraph graphs with typed state, explicit node entry/exit conditions and conditional edges.
2. Loader for the Final Gold dataset (labels, rationale, evidence URLs, QA status) with provenance and checksum.
3. Gold dataset validation report (ids, labels, cutoffs, filing dates vs cutoff, future-period claims).
4. Agentic metrics: initial vs final accuracy, verdict-change transitions (I→C, C→I, C→C, I→I),
   counter-evidence retrieval success.
5. Evidence metrics that the gold set can support honestly. Gold evidence is **not verbatim-verified**
   (v1: 129/150 `QUOTE_PENDING`; v3: 71/150 corroborated table values, not quotes), so passage-level evidence precision/recall are not computable; only
   filing-level citation overlap is.
6. Incorrect-fiscal-period rate and future-data-leakage rate as reported metrics.
7. LangGraph pilot notebook.
8. Retry policy for transient API errors (the app client has a 120 s timeout and no retries).

## 4. Potential sources of data leakage

| Source | Present control | Residual risk |
|---|---|---|
| Later filings | Form + `filed <= as_of_date` filter before reading text; XBRL facts filtered by `filed` | None found. Probe of all 174 claims: no eligible document missing, none filed after cutoff |
| Gold labels / rationales | Labels live only in workbooks under `datasets/workbooks/`; `ClaimInput` whitelist; no agent tool reads the filesystem outside the SEC cache | Low. Kept out of every prompt, tool and state |
| Model rationales in the workbooks | Same as above | Low |
| Pre-training knowledge of post-cutoff facts | Evidence rules require citations; guards revert decisive changes without a valid citation | Cannot be fully prevented; reported |
| Claims drafted with AI assistance | — | Claim wording may echo filing text; reported |
| Claim category in the model input | Category is not a `ClaimInput` field and is not in the graph state | None. Withheld on purpose: "ambiguous" correlates with INSUFFICIENT_EVIDENCE (28/50) |
| Development / gold overlap | `check_split_separation` (ids + normalised text) | None found |
| Prompt tuning on gold | Gold split needs `allow_gold=True` | Procedural: freeze prompts before the gold run |

## 5. Risks to experiment validity

1. **Reference labels are not independent human gold.** Three LLMs annotated, AI-assisted adjudication, then
   researcher review. Final labels agree with GPT-6.0 Astra on 84% of disputed claims. Results must be reported
   as agreement with this reference, with its provenance.
2. **Model family overlap.** Claude Opus 5.5 was an annotator; the experiment model is a Claude model.
3. **Gold evidence not fully verbatim-verified** (v3: 58 prose quotes matched, 16 passages checked, 71 table values corroborated, 5 no eligible filing).
4. **Low inter-annotator reliability on interpretive (α = 0.436) and ambiguous (α = 0.377) claims.**
   Accuracy on those categories has a noisy reference.
5. **Unequal reasoning budget.** A3 and SR make 3 LLM calls per claim; A1/A2 make 1. SR exists as the
   equal-budget control; A3 also issues up to 3 extra retrieval queries.
6. **Numeric override.** A2's deterministic rule is re-applied after the second look, so A3/SR cannot change
   purely numeric claims whose checks are all TRUE or any FALSE.
7. **Five future-period claims** (AAPL-04, AMZN-05, MSFT-05, NVDA-05, WMT-05): period ends after the
   cutoff or no filing yet covers it. Reference label INSUFFICIENT_EVIDENCE; the Unusable sheet suggests
   rewrites, but the Final sheet keeps the original wording — the original wording is what is evaluated.
8. **Fiscal Q4.** Q4 = FY − 9M is derived only for MSFT; other companies' fiscal-Q4 quarters return
   UNVERIFIABLE. Affects DEV-MSFT-02 (derived, works) and GOLD-AAPL-04 / AMZN-05 (future claims anyway).
9. **Temperature 0 is not fully deterministic**; repeated runs are needed for run-to-run variance.
10. **n = 150** gives wide confidence intervals; per-category n = 50.

## 6. Implementation plan (executed in this order)

1. Fix B2 (amendments) in both copies of the eligibility rule; rebuild the corpus manifest; test.
2. Reference-label loader + gold validation report (`engine/reference.py`, `scripts/validate_gold.py`).
3. LangGraph graphs (`research/graphs/`): shared typed state, nodes wrapping the existing stage functions,
   conditional edges, retry policy, trace recording. Parity test against the pre-LangGraph runners on the
   mock LLM, then the runners delegate to the graphs.
4. Agentic, fiscal-period and leakage metrics.
5. Notebooks: gold validation + LangGraph pilot; evaluation notebooks read the reference labels.
6. Mock end-to-end pilot on development claims; full offline test suite.
7. No paid run. The first real run is a development pilot that needs the approval phrase.
